---
title: One word different
date: 2026-08-04
description: The project got a new name, one word different. Renaming is mostly not the name. It is every place the old one is written down.
---

The name changed today. Build With a Memory is now Build With the Memory.

One word. I sat with it longer than one word deserves, and I still think it is
right. "A memory" sounds like a feature you bolt on, one of many, and you could
have a different one next week. "The memory" is the thing itself. There is one,
it is yours, and everything else reads from it. That is what the method actually
argues, so the name should say it.

The site is at buildwiththememory.com now. The old domain sends you there.

The rest of the day was not the name. It was every place the old name was
written down. The README. THE-METHOD. CONTEXT. The feed generator, which had the
old address baked into both the base URL and the channel title, so the feed had
to be regenerated rather than edited. A check in the release script that asserts
the name is correct, which is a nice problem to have, because it means the check
caught me. And the wizard's entry file, which is renamed with a stub left behind
at the old path, because people have that path saved in instructions I cannot
reach or update.

I amended the decision record rather than rewriting it. The original entry still
says what I chose in July and why, and the new one says what changed on August 4
and why. Rewriting it would have left a document that looks like I always
thought this, which is a small lie, and decision records are worth nothing if
they only ever agree with the present.

The repo itself is still at the old slug as I write this. That is a separate
call and I have not made it yet.

Which is the honest ending here. A rename is not an event, it is a slow leak.
Every link I have ever written points at the old name, and they all still work
right now because the host quietly forwards them. That forwarding is doing a lot
of load bearing work and it is invisible, which means the day it stops, or the
day I move something it does not cover, I will not find out from a broken page.
I will find out from someone telling me a link is dead.

I do not have a good answer for that yet. I just know that "it still works" and
"it is correct" have stopped being the same sentence in this repo, and I would
rather write that down now than discover I forgot.
